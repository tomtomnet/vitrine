# vmview

The VM display: QEMU's D-Bus display (`-display dbus,p2p=yes,gl=on`) drawn
into a native Wayland surface. The guest's buffers are attached as they are
when the sizes match (zero copy), or copied into the window's own buffers,
and QEMU is told when each frame reached the screen.

The client files here come unchanged from the D-Bus display client of the
qemu-gui research (embed-poc), where the frame path keeps being worked on.
Keep them unchanged, so that its changes port over by copying the files:
`sha256sum -c UPSTREAM.sha256` lists the files that no longer match the
version taken. vitrine's own code is `vmview.{h,cpp}`: it attaches to a
running QEMU and puts the display in a widget, or in a window of its own
for full screen.

| file | what it does |
|---|---|
| `qmp` | QMP over a connected socket, with fd passing (`getfd`) |
| `dbusdisplay` | org.qemu.Display1: console, input, UI info |
| `listener` | org.qemu.Display1.Listener on its own thread: frames from QEMU |
| `framemailbox.h` | hands frames from the listener to the renderer |
| `renderer` | render thread: zero copy or copy, commit, presentation feedback |
| `swapchain` | the window's own dma-buf buffers |
| `displaywindow` | the QWindow: input, grab, cursor, guest size |
| `waylandextras` | shortcut inhibition, pointer lock, relative motion |
| `stats` | per-second frame and latency statistics |
| `keymap_linux_to_qnum.h` | evdev key codes to QEMU's (generated by keycodemapdb) |
